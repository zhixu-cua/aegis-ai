# Qwen3:0.6b 微调与多模态 RAG 融合系统设计方案

本文档旨在设计一套基于 `Qwen3:0.6b` 的微调策略，并将其与支持多文件格式解析的 RAG（检索增强生成）系统相结合，打造一个高精度、低幻觉的专属智能售后助手。

---

## 一、 GitHub 业界开源生态参考

在 GitHub 上，微调大模型与构建 RAG 系统已经有非常成熟的开源生态。我们本方案的设计深度参考了以下顶级开源项目：

1. **大模型微调框架**：
   - [hiyouga/LLaMA-Factory](https://github.com/hiyouga/LLaMA-Factory)：目前 GitHub 上最火爆、最易用的微调框架。支持 Qwen 全系列模型，提供 WebUI，只需点点鼠标即可完成 SFT（指令微调）、LoRA 训练以及 GGUF 格式导出。
   - [modelscope/ms-swift](https://github.com/modelscope/ms-swift)：阿里魔搭社区开源的轻量级微调框架，对 Qwen 体系支持极佳。
2. **多格式文档解析引擎**：
   - [Unstructured-IO/unstructured](https://github.com/Unstructured-IO/unstructured)：目前 RAG 领域最强大的非结构化数据解析库，一站式支持 PDF、Word、Excel、PPT、图片等数十种格式。
   - [LangChain / LlamaIndex](https://github.com/run-llama/llama_index)：业内标准的 RAG 编排框架。

## 二、 RAG 多格式文档解析设计 (Doc, Docx, PDF, Excel 等)

为了让 RAG 支持多种文件后缀，必须在系统中引入 **ETL (提取、转换、加载) 层**。

### 1. 技术选型与解析策略
Python 拥有最完善的文档解析生态，因此这部分逻辑应集成在现有的 FastAPI 服务中：

*   **PDF (`.pdf`)**: 
    *   **工具**: `pdfplumber` 或 `PyMuPDF` (fitz)。
    *   **策略**: 提取纯文本。如果遇到表格，将其转换为 Markdown 格式 (`|列1|列2|`)。如果遇到图片，可配合 OCR 提取。
*   **Word (`.doc`, `.docx`)**:
    *   **工具**: `python-docx`。如果是老旧的 `.doc`，可使用 `antiword` 或通过 `LibreOffice` 转换为 `.docx`。
    *   **策略**: 按段落 (Paragraph) 提取，保留原有层级结构。提取 Table 并转为 Markdown。
*   **Excel (`.xlsx`, `.csv`)**:
    *   **工具**: `pandas`。
    *   **策略**: **绝对不要按字数切分！** 必须按行切分，并将表头与行数据拼接。例如将一行转化为文本：`当 [列A] 为 [值A] 时，[列B] 是 [值B]`，以此保留结构化语义。
*   **图片 (`.png`, `.jpg`)**:
    *   **工具**: `PaddleOCR` (开源界中文识别效果最好的库)。
    *   **策略**: 提取图片中的文字坐标，按从上到下、从左到右重组为文本段落。

### 2. 解析架构流向
1. 前端放开文件上传限制（`accept=".pdf,.docx,.xlsx,.png"`）。
2. Spring Boot 接收文件并暂存。
3. 异步调用 Python FastAPI 的解析接口，FastAPI 根据后缀名调用不同的解析器。
4. **语义分块 (Chunking)**：解析后的长文本通过 `LangChain` 的 `RecursiveCharacterTextSplitter` 按标点符号进行分块，保证句意完整。
5. 存入 PostgreSQL (`kb_chunk`) 和 pgvector 向量库。

## 三、 Qwen3:0.6b 指令微调 (SFT) 方案

小参数模型（0.6B）最大的问题是“容易被 Prompt 绕晕”和“胡编乱造”。微调的目的**不是让它背诵知识**，而是**规范它的回答格式，教会它“基于文档回答”和“学会拒答”**。

### 1. 微调数据集构建 (核心)
您需要构建约 1000 - 2000 条 JSON 格式的微调数据。格式必须与 RAG 系统推理时的 Prompt 完全一致。

**正向样本 (教会它阅读和提取，占比 60%)**：
```json
{
  "instruction": "请你作为专业的售后知识库助手，根据以下【参考文档】来回答用户的问题。优先使用文档信息，若文档不够可补充。",
  "input": "【参考文档】\n文档片段：遇到登录报错404，请检查Nginx代理。\n\n【用户问题】\n登录报404咋办？",
  "output": "您好！根据参考文档，遇到登录报错404，请检查您的Nginx代理配置是否正确。如果您还需要其他帮助，请随时告诉我！"
}
```

**负向样本 (教会它闭嘴，克制幻觉，占比 30%)**：
```json
{
  "instruction": "请你作为专业的售后知识库助手...",
  "input": "【参考文档】\n文档片段：如何更换打印机墨盒...\n\n【用户问题】\n登录报404咋办？",
  "output": "抱歉，您提供的参考文档中并未包含关于“登录报错404”的解决方法。请您提供更详细的信息或联系人工售后支持。"
}
```

**通用闲聊样本 (防止灾难性遗忘，占比 10%)**：
```json
{
  "instruction": "请你作为专业的售后知识库助手...",
  "input": "【参考文档】\n\n\n【用户问题】\n你好，你是谁？",
  "output": "您好！我是 Aegis 智能售后助手，专门为您解答系统使用过程中的问题。请问有什么我可以帮您的？"
}
```

### 2. LLaMA-Factory 微调流程
1. **环境准备**：克隆 `LLaMA-Factory` 项目并安装依赖。
2. **启动 WebUI**：运行 `CUDA_VISIBLE_DEVICES=0 llamafactory-cli webui`。
3. **配置参数**：
   - **模型路径**：选择本地的 `Qwen/Qwen2.5-0.5B-Instruct` 或 `Qwen1.5-0.5B` 权重。
   - **微调方法**：选择 `LoRA` (低秩自适应微调，不改变原模型，只训练附加层，显存占用极小，8G 显存即可跑)。
   - **训练参数**：Epoch 设置为 3-5，Learning Rate 设置为 `2e-4`。
4. **导出模型**：训练完成后，在 WebUI 中将 LoRA 权重与基础模型合并。
5. **GGUF 转换**：使用 `llama.cpp` 将合并后的模型转换为 `.gguf` 格式，然后在 Ollama 中通过 `Modelfile` (使用 `FROM ./model.gguf`) 导入。

## 四、 常见问题及避坑指南 (Troubleshooting)

### 1. 灾难性遗忘 (Catastrophic Forgetting)
- **现象**：微调后，RAG 问答很准，但用户问“你好”，它也强行按 RAG 的模板输出“根据文档...”。
- **修复与避免**：务必在数据集中混入 10%-20% 的日常闲聊数据（如问候、身份认知），且对应的 `input` 中的【参考文档】要留空，让模型学会在无文档时如何自然交流。

### 2. 模型变成复读机 (Overfitting)
- **现象**：无论问什么，它总是回答训练集里的某几句原话。
- **修复与避免**：
  - 数据集多样性不足，切忌使用脚本生成高度同质化的数据。
  - 降低训练的 Epoch 数（比如从 5 降到 3）。
  - 在 Ollama 部署时，稍微调高 `repetition_penalty` (如 1.1) 和 `temperature` (如 0.3)。

### 3. 表格与多模态信息的语义丢失
- **现象**：上传了 Excel 或含有表格的 Word，检索出来的文档虽然包含了字，但模型回答完全错乱。
- **修复与避免**：一维文本无法表达二维表格的关系。解析 ETL 层**必须**将表格转为 Markdown 格式（`| 表头 | 表头 |`）。大语言模型在预训练时见过海量 Markdown，对这种格式的理解能力极强。

### 4. 上传大文件导致解析超时
- **现象**：上传了一个 50MB 的 PDF 或几十张图片的压缩包，前端一直在转圈，最后报 500/504 错误。
- **修复与避免**：文件解析（尤其是 OCR 识别）是 CPU/GPU 密集型任务，极耗时间。系统设计必须改为**异步非阻塞模式**：
  - 前端上传文件 -> Java 落库状态设为“解析中” -> 立即返回前端“上传成功，后台处理中”。
  - Python 端后台解析，解析完向量化后，回调 Java 接口更新状态为“解析完成”。

### 5. 格式对齐失败
- **现象**：微调后不仅没变聪明，反而胡言乱语。
- **修复与避免**：在构建微调 JSON 数据集时，`instruction` 和 `input` 的拼接格式，**必须与代码中实际运行的 Prompt 完全一致**（连换行符、方括号 `【】` 都要一模一样）。如果训练时见到的格式和推理时见到的格式不同，小模型会直接崩溃。
