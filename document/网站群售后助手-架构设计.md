# 
<u>网站群售后助手架构设计</u>


## 
<u>1. 文档目标</u>


<u>本文档用于说明“网站群售后助手”MVP 版本的技术架构、模块划分、数据流、接口边界、部署方式和后续扩展方向。</u>


<u>当前设计基于以下前提：</u>


- <u>采用方案一</u>
- <u>助手系统独立部署</u>
- <u>网站群通过菜单跳转方式接入</u>
- <u>通用知识库，不区分站点</u>
- <u>当前仅做问答，不做工单闭环</u>
- <u>由个人开发者完成首期交付</u>

## 
<u>2. 总体架构</u>


<u>系统采用“Java 业务层 + Python AI 服务”的双服务架构。</u>


### 
<u>2.1 架构原则</u>


- <u>业务逻辑与 AI 能力解耦</u>
- <u>Java 负责确定性业务</u>
- <u>Python 负责检索与生成</u>
- <u>单机即可部署，后续可平滑扩展</u>
- <u>所有组件优先选择成熟、易维护、可替换方案</u>

### 
<u>2.2 架构组成</u>


- <u>接入层：网站群后台菜单入口</u>
- <u>前端层：独立部署的助手门户</u>
- <u>业务层：Spring Boot 助手管理服务</u>
- <u>AI 服务层：FastAPI 服务</u>
- <u>模型层：Ollama</u>
- <u>数据层：PostgreSQL + pgvector、Redis、MinIO</u>
- <u>观测层：结构化日志 + OpenTelemetry</u>

## 
<u>3. 模块设计</u>


## 
<u>3.1 前端模块</u>


<u>前端模块作为独立 Web 门户部署，不直接打包进网站群主工程。网站群后台只提供菜单入口，用户点击后跳转至助手系统页面。</u>


### 
<u>核心功能</u>


- <u>提问输入</u>
- <u>回答展示</u>
- <u>引用来源展示</u>
- <u>历史会话查看</u>
- <u>复制回复</u>
- <u>管理员知识库入口</u>
- <u>登录页或统一身份接入页</u>

### 
<u>前端职责边界</u>


- <u>负责交互和展示</u>
- <u>不直接调用模型服务</u>
- <u>所有请求统一走助手系统 Spring Boot 接口</u>
- <u>不依赖网站群前端框架发布</u>

## 
<u>3.2 Spring Boot 模块</u>


<u>Spring Boot 作为助手系统的管理层和统一接入层，承担以下职责：</u>


- <u>管理用户访问与权限</u>
- <u>做权限校验</u>
- <u>聚合前端请求</u>
- <u>调用 FastAPI AI 服务</u>
- <u>记录审计日志</u>
- <u>管理知识库文档元数据</u>
- <u>提供与网站群之间的接入配置</u>

### 
<u>主要子模块</u>


- <u><code data-marker="`">assistant-api</code>：问答相关接口</u>
- <u><code data-marker="`">knowledge-api</code>：知识库管理接口</u>
- <u><code data-marker="`">audit-service</code>：问答审计与操作日志</u>
- <u><code data-marker="`">auth-adapter</code>：登录与后续单点接入适配</u>
- <u><code data-marker="`">portal-config</code>：菜单入口和接入配置管理</u>

## 
<u>3.3 FastAPI 模块</u>


<u>FastAPI 作为 AI 能力层，负责：</u>


- <u>文档解析</u>
- <u>文本切分</u>
- <u>向量化</u>
- <u>检索召回</u>
- <u>Prompt 拼装</u>
- <u>模型调用</u>
- <u>回答格式化</u>

### 
<u>主要子模块</u>


- <u><code data-marker="`">ingestion</code>：文档入库处理</u>
- <u><code data-marker="`">embedding</code>：向量生成</u>
- <u><code data-marker="`">retrieval</code>：知识检索</u>
- <u><code data-marker="`">generation</code>：回答生成</u>
- <u><code data-marker="`">guardrails</code>：兜底与回答约束</u>

## 
<u>3.4 基础设施模块</u>


### 
<u>PostgreSQL + pgvector</u>


<u>用于存储：</u>


- <u>知识库文档元数据</u>
- <u>文本切片</u>
- <u>向量数据</u>
- <u>会话记录</u>
- <u>问答日志</u>

<u>选择原因：</u>


- <u>组件少</u>
- <u>学习和维护成本低</u>
- <u>单人交付更友好</u>

### 
<u>MinIO</u>


<u>用于存储：</u>


- <u>原始上传文档</u>
- <u>解析过程产物</u>
- <u>备用导出文件</u>

### 
<u>Redis</u>


<u>用于存储：</u>


- <u>用户会话缓存</u>
- <u>热点问题缓存</u>
- <u>限流计数</u>

### 
<u>Ollama</u>


<u>用于本地模型运行，作为首期默认推理方案。</u>


<u>选择原因：</u>


- <u>启动简单</u>
- <u>部署门槛低</u>
- <u>适合单机或测试环境</u>

<u>后续如并发或吞吐要求提高，可切换为 vLLM。</u>


## 
<u>4. 核心流程设计</u>


## 
<u>4.1 文档入库流程</u>


1. <u>管理员在后台上传知识文档</u>
2. <u>Spring Boot 接收元数据，原文件写入 MinIO</u>
3. <u>Spring Boot 调用 FastAPI 启动入库任务</u>
4. <u>FastAPI 解析文档文本</u>
5. <u>对文本执行清洗与切分</u>
6. <u>调用 embedding 模型生成向量</u>
7. <u>写入 PostgreSQL 和 pgvector</u>
8. <u>Spring Boot 更新文档状态为“已入库”</u>

### 
<u>说明</u>


- <u>入库流程建议异步执行</u>
- <u>文档状态建议包括：待处理、处理中、成功、失败</u>
- <u>失败原因应可在管理端查看</u>

## 
<u>4.2 问答流程</u>


1. <u>用户在网站群后台点击“售后助手”菜单</u>
2. <u>浏览器跳转到独立助手系统</u>
3. <u>用户在助手系统输入问题</u>
4. <u>前端请求助手系统 Spring Boot 问答接口</u>
5. <u>Spring Boot 校验登录态与用户权限</u>
6. <u>Spring Boot 将问题转发给 FastAPI</u>
7. <u>FastAPI 检索知识库 TopK 相关片段</u>
8. <u>FastAPI 拼装 Prompt 并调用 Ollama</u>
9. <u>FastAPI 返回答案、引用来源、命中情况和建议标记</u>
10. <u>Spring Boot 写入审计日志并返回前端</u>
11. <u>前端展示结果并支持复制回复</u>

## 
<u>4.3 拒答与兜底策略</u>


<u>当出现以下情况时，系统应拒绝给出确定性结论：</u>


- <u>未检索到足够相关内容</u>
- <u>检索片段内容冲突明显</u>
- <u>用户问题过于模糊</u>

<u>系统返回策略应包括：</u>


- <u>明确说明当前依据不足</u>
- <u>给出建议补充的信息</u>
- <u>提示转人工处理</u>

## 
<u>5. 回答策略设计</u>


<u>为降低模型幻觉，回答生成应遵循以下约束：</u>


- <u>优先依据检索结果回答</u>
- <u>不允许凭空扩展不存在的操作步骤</u>
- <u>输出结构固定为：</u>

  - <u>问题结论</u>
  - <u>排查步骤</u>
  - <u>引用来源</u>
  - <u>是否建议人工处理</u>

<u>示例输出格式如下：</u>


```text
结论：
该问题通常由模板未发布或静态页未重新生成导致。

建议步骤：
1. 检查栏目模板是否已保存并发布
2. 检查静态页生成任务是否执行成功
3. 检查页面缓存是否已清理

引用来源：
1. 模板发布说明.docx
2. 静态页生成常见问题.md

建议：
如果以上步骤无法解决，请转人工排查模板路径和生成日志。
```

<u>8. 安全设计</u>


### 
<u>8.1 鉴权原则</u>


- <u>前端不直连 FastAPI</u>
- <u>统一由助手系统 Spring Boot 校验登录态后转发</u>
- <u>FastAPI 仅开放内网访问</u>

### 
<u>8.2 接入策略</u>


- <u>网站群主系统仅新增菜单或入口链接</u>
- <u>助手系统与网站群代码、发布流程、运行环境相互隔离</u>
- <u>首期可采用独立登录，后续可扩展单点登录或票据透传</u>

### 
<u>8.3 数据安全</u>


- <u>审计日志中尽量记录摘要而非完整敏感内容</u>
- <u>上传文档应限制类型和大小</u>
- <u>删除文档时需要同步删除向量和切片数据</u>

### 
<u>8.4 提示注入防护</u>


- <u>系统 Prompt 固定，不接受前端覆盖</u>
- <u>检索内容进入 Prompt 前做基础清洗</u>
- <u>回答必须依附引用来源</u>

## 
<u>9. 部署设计</u>


## 
<u>9.1 推荐部署方式</u>


<u>MVP 推荐使用单机 Docker Compose，部署以下服务：</u>


- <u><code data-marker="`">assistant-web</code>：独立助手前端</u>
- <u><code data-marker="`">web-backend</code>：Spring Boot</u>
- <u><code data-marker="`">ai-service</code>：FastAPI</u>
- <u><code data-marker="`">postgres</code>：PostgreSQL + pgvector</u>
- <u><code data-marker="`">redis</code></u>
- <u><code data-marker="`">minio</code></u>
- <u><code data-marker="`">ollama</code></u>

## 
<u>9.2 环境建议</u>


- <u>开发环境：Windows 10/11 + Docker Desktop，代码在本机 IDE 中开发调试</u>
- <u>试运行环境：单台 Linux 内网服务器，使用 Docker Engine 与 Docker Compose 插件部署</u>
- <u>后续扩展：按服务拆分到多节点</u>

## 
<u>9.3 环境兼容策略</u>


- <u>本地开发以 Windows 为主，但容器内运行环境按 Linux 目标环境设计</u>
- <u>服务间调用使用 HTTP、数据库连接和对象存储，不依赖本机文件系统绝对路径</u>
- <u>文档原文通过 MinIO 管理，系统内部传递 <code data-marker="`">bucket</code> 与 <code data-marker="`">objectKey</code>，避免传递 <code data-marker="`">C:\</code> 这类 Windows 路径</u>
- <u>配置通过环境变量管理，避免把主机名、端口、账号写死在代码中</u>
- <u>如需本地 GPU 推理，可在 Windows 先用 Ollama 验证；Linux 部署时再按服务器条件调整模型与资源</u>

## 
<u>12. 技术选型说明</u>


### 
<u>为什么选择 Spring Boot + FastAPI</u>


- <u>与现有 Java 网站群体系兼容性高</u>
- <u>AI 能力部分使用 Python 生态更高效</u>
- <u>业务与模型能力解耦，后续替换成本低</u>

### 
<u>为什么选择独立系统 + 菜单跳转</u>


- <u>对网站群主代码改动最小</u>
- <u>部署、回滚和故障定位更简单</u>
- <u>更适合个人开发者逐步演进</u>
- <u>后续更容易扩展成多系统复用的售后平台</u>
- <u>Windows 开发与 Linux 部署之间的切换成本更低</u>

### 
<u>为什么选择 PostgreSQL + pgvector</u>


- <u>相比单独引入专用向量库，部署更轻</u>
- <u>更适合个人开发和 MVP 场景</u>

### 
<u>为什么选择 Ollama</u>


- <u>首期部署简单</u>
- <u>支持本地模型</u>
- <u>适合作为 MVP 推理层</u>

## 
<u>13. 单人开发建议</u>


- <u>严格控制范围，只做问答闭环</u>
- <u>优先完成“上传文档 -> 可检索 -> 可回答 -> 可审计”</u>
- <u>不要在首期引入过多流程引擎和复杂消息系统</u>
- <u>先把结构做成可替换，再考虑复杂能力</u>
